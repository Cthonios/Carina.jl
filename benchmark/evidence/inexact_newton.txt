Inexact Newton (Eisenstat-Walker forcing terms): CPU and A100 A/B
=================================================================

Verdict: a real win in both implicit regimes, largest where the linear solve
dominates the step.  Per-step wall on the A100 improves 1.45x for Newmark
dynamics and 1.59x for quasi-static AMG, on top of everything the earlier GPU
campaigns bought, and without a single new kernel.  Shipped OFF by default (a
deck must ask for it); when asked for, `maximum` defaults to 0.2 -- not the 0.9
of the original paper.  See "Why 0.2" below.

Motivation.  Carina drove every Newton iteration's linear solve to the deck's
`tolerance`, however far the *nonlinear* residual still was from converged.
Two independent measurements showed the same waste:

  torsion / Newmark / A100    CG 181, 205, 193 per Newton iteration while
                              |R| fell 1.61e4 -> 1.34e2 -> 7.79e-2 -> 4.60e-8
  J2 specimen / QS / CPU      CG ~350 on each of the first seven iterations
                              while |R| crawled 1.57e3 -> 1.76e2, after which
                              the line search backtracked to alpha = 0.25

In both, only the last solve needed eight digits.  A forcing term makes the
tolerance per-iteration:  eta_k = gamma (|R_k|/|R_k-1|)^alpha  (Eisenstat &
Walker, SIAM J. Sci. Comput. 17(1):16-32, 1996, choice 2), guarded by EW's own
safeguard, Kelley's over-solve guard, and a clamp.

Safety property.  eta is clamped to [rtol, eta_max], so a forcing term can only
ever LOOSEN a solve, never tighten one.  The final Newton iterations run at
exactly the tolerance the deck asked for, the converged answer is unchanged,
and an A/B against `fixed` compares like with like.  Confirmed empirically:
|U|_max agrees to every printed digit at every stop of every pair below
(Newmark 5.16e-03 / 1.07e-02 / 1.64e-02 / 2.20e-02; QS 1.28e-03).

Hardware / software.  Date: 2026-08-29.
  CPU   sirius desktop, 8 Julia threads, Julia 1.12.6
  A100  ascicgpu073, NVIDIA A100-PCIE-40GB, CUDA via CUDA.jl, Julia 1.12.6
Both A100 passes ran under the shared-home flock; the host was otherwise idle
(two A100s present, one used).  The CPU sweep ran on an otherwise-quiet
machine; an earlier contended run of the same pair is discarded, not reported.

-------------------------------------------------------------------------------
4. Why 0.2, and why it is not a tuning accident
-------------------------------------------------------------------------------
Total CG work is nearly INVARIANT in eta_max -- 63.1k / 62.9k / 63.6k on CPU,
1019 / 1011 on the A100.  What eta_max actually controls is how many Newton
iterations you spend buying that work, and there the spread is large: 413 vs
547 on CPU, 19 vs 25 on the A100.

The mechanism is EW's own safeguard, which holds eta up whenever
gamma*eta_prev^alpha > 0.1.  With the default alpha = (1+sqrt5)/2:

    eta_max = 0.2  ->  0.2^1.618 = 0.076   below the knee, safeguard idle,
                                           the residual ratio drives eta
    eta_max = 0.5  ->  0.5^1.618 = 0.326   above it, safeguard permanently on,
                                           eta pinned high for several
                                           iterations
    eta_max = 0.9  ->  0.9^1.618 = 0.842   far above; the paper's value

So 0.2 is not a fitted constant: it is the largest round value that keeps EW's
anti-collapse safeguard out of the way of its own adaptivity.  Two problems on
two architectures picked it independently.  0.1 also works but converges
Newton slightly worse (432 vs 413 iterations on CPU) by tightening solves the
ratio would have left loose.

-------------------------------------------------------------------------------
5. Interaction found and fixed: the AMG staleness detector
-------------------------------------------------------------------------------
The detector latches a baseline from the first CG count after a hierarchy build
and rebuilds when a later count passes 3x it.  Under a forcing term those
counts come from solves at different tolerances and are not comparable as raw
numbers.

Skipping loosened solves is not a fix: the over-solve guard means a run can
converge without ever solving at the deck's tolerance, and the detector is the
ONLY rebuild trigger on the quasi-static path (`_build_precond_op` passes
c_M = 0 there, so the c_M test never fires).  Quasi-static AMG would then build
once at the reference configuration and keep it for the whole load history --
the 63 -> 400 iteration drift that test/amg-staleness.jl exists to prevent.

`_tracked_iters` rescales a count by the digits of residual reduction the solve
was asked for.  At rtol_eff == rtol it is exactly the identity, so a run with
no forcing term feeds the detector precisely the numbers it always did.

6. Reproduction
-------------------------------------------------------------------------------
Deck syntax (nested under solver.linear solver):

    forcing term:
      type: eisenstat-walker     # aliases: eisenstat walker, ew, adaptive
      maximum: 0.2               # eta_max; default 0.2
      # initial / gamma / exponent / safety factor all optional

An absent block means `fixed` -- every deck written before this existed is
unaffected.  Unknown types and out-of-range values are hard errors; unknown
keys warn through the input-key walker.

CPU:  the four decks of section 1 are the shipped tension-specimen-j2 deck with
`final time: 0.05`, `output interval: 1.0e9`, and the block above.
A100: ~/ew_sweep.sh and ~/ew_sweep2.sh on ascicgpu073 generate all eight decks
from benchmark/inputs/ and run them under flock; results in /scratch/amota/ew.
Both remote scripts hold $HOME/.carina_sweep.lock for the whole sweep --
ascicgpu073 and ascicgpu24 share one NFS home and one ~/.julia depot.
